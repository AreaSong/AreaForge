# v1.3-v2.0 A -> B 平台演进

## 当前状态

- 当前计划状态：已确认总体方向，M0 已完成，v1.3 本地实现执行中；v1.4-v2.0 runtime 尚未开始。
- 当前生产：`v1.1.1`；最新稳定 GitHub Release：`v1.2.0`；当前开发分支已包含尚未合并的学习闭环、多科目/分组首次设置、通用模板、科目 CRUD、重复识别和安全预览。
- v1.3 尚缺真实科目合并写入、空库完整旅程收口、受保护 PR/CI、签名 Release 和独立 production apply；这些状态不能由已有本地代码代替。
- 本计划不把规划、隔离实现、Release 或 production apply 混为同一完成状态。

## 目标

在不破坏个人长期备考闭环的前提下，把 AreaForge 从单管理员私有应用逐步演进为邀请制多人学习平台。最终同时具备个人 Workspace、多用户成员关系、统一权限、可验证的数据生命周期、受控运维、主动加入的挑战排名和多人平台运营能力。

## Planning Gate

- 目标：A（个人完整产品）稳定后渐进到 B（多人学习平台）。
- 非目标：通用团队项目管理、任意 shell、默认公开排名、企业组织树、SSO/SCIM、计费、小程序、原生 App、AI 自动应用完整计划。
- Exact docs：`docs/product/charter.md`、`docs/product/feature-scope.md`、`docs/product/roadmap.md`、`docs/development/feature-traceability.md`、本文件。
- Open questions：各版本冻结时确定精确 migration、API、页面、角色矩阵、保留期和生产窗口；未冻结项不能凭总体确认直接推断实现细节。
- Decisions：个人路径优先；邀请制先于公开注册；预设角色先于自定义权限；导出先于物理删除；私有挑战先于公开排行；operation intent 取代任意 shell。
- Owner skill：`areaforge-operating-loop` 统筹；产品、安全、文件、SRE、供应链、验证和文档由对应 owner skill 负责。
- Validation profile：每批按风险选择 core/Web/Prisma/API/浏览器/跨租户/文件/ops/Release/生产证据，不以 `pnpm check` 单独证明高风险能力。
- Source baseline：个人学习闭环、Package A-E、`v1.2.0` Release 和当前分支科目 CRUD/闭环增强。
- Residual risk IDs：`AF-RISK-DATA-001`；新稳定风险只在 owner、关闭条件和复核周期明确后登记。
- Release trigger：每个可部署版本独立受保护 PR、CI、签名 Release 和 production apply 确认。
- Apply boundary：Web runtime 不直接执行服务器命令；migration、删除、备份、恢复、updater apply 和 rollback 均需对应高风险确认。
- 回滚：additive-first；先回滚应用，保留兼容字段/表；数据删除和生产操作按各包备份、撤销或恢复策略执行。

## 不变产品契约

1. 个人用户无需邀请成员、配置权限或参加排名即可完成全部学习闭环。
2. 学习源事实归用户和 Workspace 所有；排名、通知、搜索和 AI 都是派生消费者。
3. 敏感内容默认私有，分享必须显式、最小化、可审计和可撤销。
4. 建议、草稿、确认和应用保持分层，不因 Coach、Admin 或排行自动改写正式记录。
5. 所有私有 API 在服务端授权；隐藏客户端按钮不构成权限控制。
6. Web runtime 不持有 root、Docker socket、生产 secrets、备份目录或自由命令能力。

## v1.4：身份、成员与 Workspace

### 批次

1. AUTH-0：威胁模型、数据归属、迁移 preimage、邀请制和会话策略。
2. AUTH-1：账户状态、邮箱验证/密码重置、设备会话和敏感操作重新验证。
3. AUTH-2：新增 `WorkspaceMembership` 和 `WorkspaceInvitation`，现有 owner 回填为 `OWNER`。
4. AUTH-3：邀请、接受、撤销、移除、离开和所有权转移；最后一名 Owner 保护。
5. AUTH-4：全链路 workspace scope、IDOR 负向测试和旧单用户兼容。

### 验收

- 两个用户可加入同一 Workspace；两个 Workspace 之间不能串读、串写或推断资源存在性。
- 成员移除和账户冻结立即影响新请求；长操作提交时重新授权。
- 旧管理员无损成为现有 Workspace Owner，个人路径不退化。

## v1.5：RBAC 与隐私授权

### 批次

1. RBAC-0：冻结 Owner/Admin/Coach/Member/Viewer 权限矩阵和敏感数据矩阵。
2. RBAC-1：统一 policy service 和 capability DTO，API/service/query 三层接入。
3. RBAC-2：敏感资源可见范围：仅自己、指定成员、Coach、Workspace。
4. RBAC-3：权限变化、敏感读取、成员操作和拒绝结果的脱敏审计。
5. RBAC-4：角色矩阵、跨租户、批量操作和 TOCTOU（检查与使用时差）回归。

### 验收

- 所有私有 API 有服务端授权；客户端不可信 actor/user/workspace 参数不能越权。
- 动机、情绪正文、完整复盘、私有笔记/附件、AI 输入和导出文件不因 Admin/Coach 身份自动可见。

## v1.6：数据生命周期

### 批次

1. DATA-0：数据清单、owner、导出/删除/审计/备份保留矩阵和 redaction matrix。
2. DATA-1：异步 Workspace/账户导出、版本化 manifest、checksums、短时一次性下载凭证。
3. DATA-2：对象回收站、影响预览、恢复期和派生投影排除/重建。
4. DATA-3：删除预览、重新验证、冷静期、冻结、取消和 `DeletionJob` 状态机。
5. DATA-4：数据库、附件和可重建投影物理删除；失败补偿和脱敏回执。
6. DATA-5：备份删除账本；历史备份恢复后重新应用 deletion ledger，避免数据复活。

### 验收

- 导出对象、附件、manifest 和 hash 一致，不包含密码 hash、session token、Provider secret 或内部路径。
- 删除预览与实际范围一致；删除后鉴权、搜索、附件、挑战和排名均不可见。
- kill-point、重试、恢复和历史备份恢复 fixture 通过后，`AF-RISK-DATA-001` 才可进入人工关闭复核。

## v1.7：受控运维中心

### 批次

1. OPS-0：只读健康、版本、agent、磁盘/证书、备份清单、维护锁和脱敏历史。
2. OPS-1：白名单 operation catalog，不接受命令文本、脚本正文、自由路径或环境变量。
3. OPS-2：expected-before、TTL、nonce、request hash、幂等、身份和审批绑定。
4. OPS-3：root-only agent phase journal、锁、超时、崩溃恢复、reconciliation 和回滚。
5. OPS-4：检查更新、备份、签名 Release apply、允许 digest rollback、受控重启、维护模式和预定义诊断逐项开放。

### 验收

- Web runtime 仍无 Docker socket、root、生产 `.env`、备份目录和签名私钥。
- 任意 shell、未登记动作和状态漂移均 fail closed。
- 每项生产动作具备独立确认、备份/hash、smoke、回滚和 redacted evidence。

## v1.8：成长指标、私有挑战与排名

### 批次

1. RANK-0：指标定义、时区、窗口、并列、版本、隐私、退出和删除规则。
2. RANK-1：个人成长指数，只与自己的历史基准比较。
3. RANK-2：主动创建/加入的私有挑战、昵称和字段授权。
4. RANK-3：可重建排名投影、异常时长、重复 session、修改/删除联动和申诉。
5. RANK-4：公开排名仅保留评审入口，不在本版本默认开放。

### 验收

- 分数带 `scoreVersion`，相同源事实可重复计算；投影故障不影响学习主链。
- 动机、情绪正文、复盘、笔记/错题内容、附件、AI prompt 和私有任务标题永不进入排行。
- 退出挑战或删除账户后可重建并移除贡献。

## v2.0：多人学习平台门禁

v2.0 不是功能开关，而是以下证据同时成立后的发布结论：

- 个人与多人核心旅程均可完成，个人用户不被成员/排行设置干扰。
- AUTH、RBAC、EXPORT、DELETE、OPS、RANKING 六个高风险包均有独立确认与完成证据。
- 跨租户、权限、隐私、导出、删除、附件、排名和后台任务回归通过。
- 受保护 PR、CI、签名 Release、不可变 digest、production apply、smoke、回滚和观察记录齐全。
- 运营具备监控、告警、审计、事故响应、数据泄露响应和误删除恢复流程。

## 统一交付门禁

每个批次按以下顺序推进：

```text
源事实 -> 威胁/体验设计 -> 任务与确认包 -> additive migration -> 实现与专项测试
-> 浏览器/API 验收 -> 受保护 PR/CI -> 签名 Release -> 独立 production apply
-> 生产 smoke/观察 -> residual 人工复核
```

代码完成、Release 完成和生产完成是三个独立状态。任一 migration、数据删除、生产写动作、权限边界或默认数据共享变化，在执行前必须有对应批次的精确影响、风险、验证和回滚确认，不能只引用本总计划。

## 风险与回滚

- 租户隔离失败：停止多人开放，撤销邀请/成员入口，保留个人 owner 兼容路径并回滚应用。
- 权限错误：fail closed，撤销新角色能力，保留审计和受影响对象清单。
- 导出泄露：立即撤销下载 grant、清理临时包、轮换相关凭证并进入 incident 流程。
- 删除错误：执行前备份和范围 hash；处理中断进入可恢复状态，禁止静默跳过文件或关联数据。
- 运维误执行：agent 进入 hold，按 phase journal 和固定 rollback target 恢复；Web 不直接接管执行。
- 排名伤害或作弊：关闭挑战/排行投影，不影响或修改个人学习源事实。
