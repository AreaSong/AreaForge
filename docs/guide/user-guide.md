# 使用指南（User Guide）

## 定位

本文面向 AreaForge 的使用者，按"每天怎么用"和"长期怎么用"讲清各页面和机制。它只写怎么用；模块的设计规则见 `docs/modules/**`，第一次上手见 [产品上手](getting-started.md)。

## 页面总览

| 路径 | 名称 | 用途 |
|---|---|---|
| `/today` | 今日作战台 | 每天的第一屏：今日任务、专注入口、复盘、风险与鞭策 |
| `/focus` | 开始学习 | 选择科目后直接进入唯一活动计时器，任务/考纲/目标时长可选 |
| `/knowledge/syllabi` | 考纲进度 | 大纲树、节点状态、作战地图、掌握证明 |
| `/knowledge/cards` | 知识卡片 | 文本笔记与私有附件，按科目/节点/掌握状态/复习提醒筛选 |
| `/knowledge/mistakes` | 错题与掌握证明 | 错题记录、错因、复习提醒 |
| `/roadmap/stages/trend` | 数据统计 | 学习时长、完成率、连续性、风险项趋势 |
| `/roadmap/reviews` | 周期报告 | 周审判与月复盘，含确认/驳回决策 |
| `/test/simulations` | 全真模拟 | 结构化模拟考试、阶段计划与调整草稿 |
| `/settings/profile` | 动机封存 | 封存开始的原因，关键节点唤醒 |
| `/settings` | 设置总览 | 查看工作区、档案、通知、AI、体验和系统配置状态 |

界面为电脑优先设计，移动端响应式适配；深浅色与状态主题随学习状态变化。

## 每日闭环

### 早上：看作战台

首页按优先级组织信息：第一优先级是当前推荐任务、开始计时和风险等级；其次是今日指标、欠账任务和考纲概览；最后是错题提醒、复盘提醒和阶段称号。连续高完成时会突出连胜，断签后会突出欠账和恢复动作。

### 白天：任务与专注计时

- 任务带科目、类型、优先级、预计时长，可关联考纲节点；状态在待开始、进行中、已完成、已延期、已放弃之间流转。
- 点"开始计时"进入专注模式：计时器放大，显示当前科目、任务和节点，其余信息弱化。支持暂停/继续；同一时间只允许一个进行中的计时，刷新页面后会自动恢复。
- 从今日推荐或队列进入任务时，任务详情和专注页会保留来源。计时过程中返回来源不会暂停或结束活动，页面会明确提示“计时继续”。
- 结束计时必须做结构化收口：学习质量评分、是否有效学习、理解程度、最小产出、下一步动作。"有效学习"的判断会进入打卡、统计和风险计算。
- 收口后可以直接在专注流程中创建知识卡片、错题或复测，不需要跳出当前页面。保存成功后会显示为本次学习证据；复测要求任务已关联考纲节点。
- 完成摘要显示服务端保存的任务状态；主操作回到今日查看刷新后的下一行动，从计划或任务详情进入时仍可返回原页面。
- 跨页面进入详情、专注或快速复习时，返回入口会直接写明“返回计划”“返回收件箱”“返回资料”“返回复习队列”等实际去向；最多保留三层逐级来源，并保留允许的筛选条件。外部地址和未登记参数不会成为返回目标。
- 页面切换时会保留导航框架，只在内容区显示加载状态。如果某个工作台暂时读取失败，可以先原地重试，也可以返回当前所属工作台；找不到某条任务、知识记录、复盘或阶段记录时，系统不会把它误认为整个应用不可用。
- 编辑任务、考纲节点、卡片、错题、资料或晚间复盘时，状态标签会区分本机草稿和服务端保存。本机草稿可在重新进入页面后恢复，但不等于已经提交；刷新或关闭浏览器前会提示仍有未提交内容，版本冲突必须由你明确采用或合并。
- 这些编辑器的底部操作区只保留一个主要保存动作。关闭并保留会继续留下本机草稿；“放弃编辑”会清除本机草稿。卡片、错题和资料在编辑期间不会同时显示归档操作，避免把保存与生命周期变更混在一起。
- 新建任务、考纲节点、知识卡片、错题或资料时，可以使用顶栏“快捷创建”，也可以点击对应列表标题区的唯一创建按钮；知识点创建留在知识工作台。两种入口会打开同一个右侧抽屉。关闭抽屉不会清除未提交草稿。单个对象保存成功后直接进入新对象详情并可返回原列表；Markdown 考纲导入和多文件上传会留在列表显示批量结果。
- 归档卡片、错题、资料或考纲节点前会显示影响确认：对象变为只读，活动复习排期会暂停。归档后仍停留在详情页，可以直接恢复对象，但需要自行重新选择复习日期。放弃有修改的本机草稿和放弃任务也会先确认；任务之后仍可通过“补做”恢复。
- 只看课没输出、只抄笔记没理解、计时很长但任务没推进，会被标记为低转化学习并纳入周报统计——这是反假学习机制，别绕它。

### 随手：笔记与错题

- 笔记支持文本和附件（PDF、PNG、JPEG、WebP），附件保存在私有目录并通过鉴权接口访问，列表不暴露磁盘路径。
- 每份资料建议写清属于哪个节点、解决什么问题、下次何时再看；上传文件不等于掌握。
- 资料页首屏只展示资料数量、科目筛选和资料列表；科目筛选会直接过滤列表。需要新增时点击页头唯一的“添加资料”，在右侧抽屉中选择文件上传或 HTTPS 外链。未完成上传和重复文件决策会保留“继续处理”入口，归档资料收在次级折叠区；创建方式的安全校验、重复处理和冲突恢复规则不因布局调整而改变。
- 知识卡片、错题和考纲页也只在列表或地图标题区保留一个创建入口，表单统一放在右侧抽屉；卡片和错题保存后进入详情，考纲单节点保存后进入节点详情，Markdown 批量导入仍停留在考纲地图查看摘要。
- 卡片、错题、考纲和资料共用知识工作台顶部搜索；页面内可继续按科目、节点、掌握、错因、复习或地图状态筛选。搜索与筛选会保留在地址中，刷新或查看详情后返回不会丢失；“清除筛选”只清除页面筛选，搜索词需要在顶部搜索栏单独清除。
- 列表项优先展示状态、标题、简短摘要和更新时间，点击“打开详情”处理完整内容。错题修改统一在详情页完成；卡片附件和考纲掌握证明在列表默认收起，需要时再展开，避免连续浏览时被编辑表单打断。
- 资料详情默认先展示资料事实和已关联的任务、卡片、错题、考纲节点；文件优先私有预览或下载，链接优先打开来源。下一行动会引导打开关联任务或创建最小学习任务；资料归档后只提示恢复，再进入学习计划。需要修改元数据与关联时再进入“整理资料”，已有未保存草稿会自动恢复。进入私有预览或关联对象后，可逐级返回资料详情和原工作台。
- 错题记录错因和复习提醒时间，到期错题会出现在作战台提醒和统计风险里。

### 批量整理：学习树导入

导入页默认只展示当前批次、历史记录和唯一“开始导入”。开始后可以下载全局、单科或分支模板，也可以选择或粘贴 Markdown；系统先生成差异预览，冲突项必须映射或跳过，校验通过后才能显式原子确认。页面中断、登录失效或学习树状态变化时会保留 Markdown 和映射，但必须重新预览最新差异，不会自动重放确认。确认成功后进入批次结果页，先看已应用/已跳过摘要，再去考纲核验；协议、哈希和规范化源只在技术校验信息中展开。导出当前学习树位于独立工作态，不与导入表单混排。

### 统一复习

知识概览会把当前最需要处理的知识行动放在第一屏：有到期排期时直接开始下一项复习，否则依次提示薄弱节点、待整理资料或最近导入。统一复习页把到期、暂停、已转正式任务和近期完成放在同一个队列中切换，顶部显示今日完成进度、逾期数量、今日到期和预计剩余时间。

快速复习会展示卡片、错题、资料或考纲节点的真实内容。确认后，系统保存本次结果与有效时长，更新连续通过次数和下次复习日期；完成态先给出唯一下一行动：有后续排期时继续下一项，没有后续时按进入来源回到今日、复习队列或对象详情；对象详情和复习历史保留为带来源的次级入口。排期或对象在确认前失效时，也会回到进入快速复习时的来源。排期详情先给出唯一下一行动，再展示对象核验内容，暂停/恢复放在排期管理区，事件历史和更正入口单独保留；状态更新异常会回到进入排期详情时的来源。卡片、错题和考纲节点详情保留各自的复习历史、排期或掌握证据，并把到期复习放在页头主操作；卡片无排期时、错题完成独立重做后，详情中的下一行动会引导首次排期；资料详情把预览、下载或打开来源作为页头主操作，并把关联/创建任务作为下一行动。所有对象详情都会保留上游来源，查看对象后仍可返回原工作台。

### 晚上：复盘

复盘页先根据当天已完成记录展示有效学习时长、任务完成、低转化、科目投入以及知识卡片、错题、复测证据；这些客观事实不需要重复填写。用户只需记录实际推进、偏差、应保留动作、可选状态和明日最低行动。保存后会同时固化当日打卡快照，并把明日最低行动写入投入草稿收件箱；完成态可直接打开这条草稿，补全科目与预计时长后转为正式任务，转换成功后进入新任务详情。任务详情会保留“返回复盘”或“返回收件箱”的来源，不会误回投入安排页。启用 AI 后可生成复盘建议和明日投入草稿；AI 不会覆盖原始复盘。

## 长期机制

### 打卡与连续性

打卡不等于打开应用，必须完成至少一次有效学习动作（一段计时 + 收口）。连续打卡、断签次数、连续低效天数会影响风险等级、鞭策语气和阶段称号。

### 任务债务

未完成任务自动进入欠账池，按影响分为可接受、需要补、影响阶段、计划崩坏四级。处理方式有补做、延期、拆小、合并、放弃、改成复习任务。系统会生成重排建议，但从不自动应用：你在首页任务区勾选建议项后，显式确认、驳回或应用所选。

### 考纲进度与掌握证明

- 节点状态覆盖未开始到掌握、薄弱、放弃暂缓；支持打勾、打叉、星标、警告标记。
- 作战地图聚合所有科目进度，标出薄弱、遗忘风险、错题高发区域并给出优先处理节点和下一步动作。
- 考纲页首屏优先显示作战地图、节点树和当前行动；“考纲遗忘风险”默认收起为摘要，展开后可查看完整风险来源、证据新鲜度、重点科目和下一步动作。
- 打开节点详情后，页面会先显示该节点当前下一行动：没有复习排期时可直接创建已带科目和节点的最小学习任务，已有排期时进入排期管理，到期时从页头开始复测。掌握证据、复测历史和节点编辑分别在对应视图或管理入口中处理。
- 把节点标为"掌握"需要证据：可设置掌握条件（看完课、写过理解、做过题、错题复盘、延迟复测），并引用同节点下的任务、计时、笔记、错题或复测记录作为显式证据。证据不足时系统会拒绝写入掌握状态——打勾只是状态，掌握需要证明。
- 复测记录 `passed/failed/partial`；只有通过计入延迟复测证据，失败只留历史，不自动降级。

### 恢复模式

连续断签、完成率长期过低或你主动点"我需要恢复"时进入恢复模式。作战台聚焦一个最小可执行任务（默认目标 30–90 分钟），不强制补完所有欠账；完成恢复任务后逐步回到正常计划。文案严肃但不羞辱。

### 周审判与月复盘

`/roadmap/reviews` 的周审判汇总一周真实执行（时长、完成率、欠账、低转化、错题、最大短板和下周必须压住的一个问题）；月复盘检查阶段计划是否仍然有效。页面先给出唯一最大短板和下周期焦点，再下沉展示执行事实、科目投入、判断依据与待确认动作。确认会冻结报告并把动作草稿送入投入草稿收件箱，你需要逐项补全或转成正式任务；如同时生成阶段建议，还要在阶段概览独立确认。完成态会区分新生成、复用已有草稿和没有草稿三种结果，不会在没有可处理内容时仍引导进入收件箱。整个过程不会直接修改现有任务或当前阶段。

`/roadmap/stages` 始终区分当前生效阶段、待确认建议和最近处理结果。有待确认建议时先决定是否应用；确认后阶段计划才会更新，派生任务仍先进入投入草稿。`/roadmap/stages/trend` 会把当前最高风险和对应处理入口放在趋势数据之前，便于从风险直接回到投入安排、周期复盘、知识复习或今日行动。

### 全真模拟与阶段调整

`/test/simulations` 会优先显示最近未完成的模拟考试；没有草稿时再创建新模拟。进入考试后按三步处理：先录入分科目标分、实际分、用时和空题，再把失分按原因、考纲节点和分值结构化记录，最后核对心态与整场总结并确认考试事实。确认后成绩与失分冻结为只读，页面才会开放补救选择。

选中的补救只会进入 `/roadmap/allocation/drafts`，不会直接生成任务。页面会记住每条补救当前是已入箱、已忽略还是已转任务；刷新后这些项目保持不可重复发送。你需要在投入草稿中补全日期等字段并显式转为正式任务；如模拟结果意味着阶段方向需要变化，再进入 `/roadmap/stages` 独立生成或确认阶段建议。补救入箱和阶段确认都不会自动重排现有任务。

### 阶段称号、鞭策与动机

- 阶段称号（初醒、入炉、淬火、重铸、稳态、破局、冲刺）按连续打卡、时长、完成率等计算，影响首页展示、鞭策语气和动态主题。
- 鞭策引擎按上升期到危险期的真实状态选择语气：学得好继续加压，学得差给最低可执行动作，不灌鸡汤也不只批评。
- `/settings/profile` 封存你开始的原因和给未来自己的话，只在连续失守、重大复盘、模拟前后等关键节点唤醒，不每天出现。

## AI 边界（使用者视角）

- AI 需要在配置中显式启用（见 [配置参考](configuration.md)），并且只在你显式触发时调用。
- AI 产出的一切都是建议或草稿：复盘建议、明日任务草稿、阶段调整草稿，均需确认后生效。
- 默认不发送给 AI：动机档案、完整情绪记录、完整复盘正文、附件内容、完整任务标题。情绪标签可以进入上下文。
- AI 不可用或失败时自动回退到本地规则，功能不中断。

## 设置与版本中心

`/settings` 是设置总览，先汇总工作区、档案与动机、通知、AI、体验和系统六类状态。首次使用时先进入 `/settings/exams?setup=1`，完成考试目标、首个科目和已有数据处理后返回 `/today`；其余设置按需补充，不阻断开始学习。

`/settings/profile` 按“动机封存 -> 当前设备提醒 -> 可展示内容库”组织。动机封存正文默认不进入 AI；只有显式选择的摘录可以加入内容库，AI 草稿入口默认折叠且只在主动提交时触发。

版本与运行状态位于 `/settings/system`。版本中心只做两件事：查看当前版本与更新通道状态、提交受控更新请求。它不会在网页里执行更新——签名校验、备份、migration、切换和回滚全部由服务器侧完成。更新策略的含义见 [配置参考](configuration.md) 和 [GitHub Release updater](../deployment/github-release-updater.md)。
