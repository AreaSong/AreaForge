# 成员席位与活跃任务总量

## 配置与范围

成员席位和后台任务总量分别由 `WORKSPACE_MEMBER_QUOTA_ENABLED`、`DATA_JOB_TOTAL_QUOTA_ENABLED` 控制，默认关闭。
限额只在新的对应准入解析，不由浏览器传入；开启后必须显式配置规范十进制整数，没有隐式生产阈值。
实现和验收状态见[平台加固任务](../../tasks/backlog/0045-platform-hardening.md)。

| 配置 | 含义 |
|---|---|
| `WORKSPACE_MEMBER_QUOTA_MAX_SEATS` | 工作区成员席位，至少一席，包含 Owner |
| `DATA_JOB_TOTAL_QUOTA_MAX_ACTIVE_USER` | 同一用户在全部工作区及 ACCOUNT 桶的活跃任务总量 |
| `DATA_JOB_TOTAL_QUOTA_MAX_ACTIVE_WORKSPACE` | 同一工作区内所有请求者的活跃任务总量；ACCOUNT 无该桶 |
| `DATA_JOB_TOTAL_QUOTA_MAX_ACTIVE_INSTANCE` | 同一数据库实例三类受控任务的活跃总量 |

任务上限允许零；所有上限最大为 `2147483647`。缺失、负数、小数、指数形式、前导零或越界值拒绝新准入，
但不阻断登录、学习、个人工作区建立、读取、退出/移除成员及既有任务控制。

## 成员席位

以 `ExamWorkspace.userId` 预留一席 Owner，加原始成员表中 ACTIVE 且非该 Owner 的行数。
停用账户、冻结对象或归档工作区不释放席位；LEFT/REMOVED 释放。该占用不同于页面上的当前可见/可用人数，不能复用普通可见性 count。
Owner 关系继续由既有权限策略校验，配额不修复、降级或驱逐成员；正常所有权转移不增加席位。

待接受邀请不预占席位，也不保证接受时仍有空位。接受在原邀请、身份、到期和 revision 检查后进入同一可序列化事务，
检查席位并提交成员变化；失败回滚新账户、个人工作区、邀请状态和审计。已有 ACTIVE 成员不重复计量。
已消费邀请仍按原语义拒绝，不能用配额重试把一次性 token 变为可重放凭证。

## 活跃任务总量

仅覆盖 EXPORT、SEARCH_INDEX_REBUILD、RANKING_REBUILD 的持久协议任务；保留[分区任务配额](data-job-quotas.md)作为独立约束。
有效期内的 QUEUED、RUNNING、PAUSED、CANCEL_REQUESTED、FAILED 都占位；成功、已确认取消或到期释放。
计量不隐藏停用、冻结或归档范围的未结算任务。总量是准入记录上限，不等于实际进程并发数。

所有新准入使用 Serializable；全局准入锁先于分区配额锁，有界锁/语句超时，计数与任务、审计和搜索代次同事务提交。
同键绑定和授权先于配额，已有回执不重复计量；旧快照冲突必须回滚或从新事务重试。新旧构建或不一致配置混跑不提供总量保证。
计量只返回受控拒绝，不向调用者披露其他用户/工作区的标识、正文或数值。

## 失败与回退

确定超额返回 429；未知用量、坏配置或短时竞争返回有界服务错误。邀请页保留输入及未消费凭证，允许手动重试并聚焦反馈；
不伪造等待时长，不把超额说成邀请失效。已有超额数据保留，只限制增加占用的请求。
总量开启时，新增导出准入事务的已识别竞争映射为 `DATA_JOB_QUOTA_BUSY`（503）；关闭模式、既有导出控制与下载继续沿用原冲突语义，不把授权拒绝改写成配额错误。

关闭两个新增开关撤回新增准入限制，保留成员、任务、审计和旧分区配额；不删除数据、不改其他域开关。
本规则不提供存储配额、待接受邀请数量限制、跨分区导出次数账本、删除后计量留存或支付计费。
