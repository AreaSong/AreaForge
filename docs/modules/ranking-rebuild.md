# 持久排名重建

## 角色与边界

私有挑战的所有者可以显式申请重建；请求者同时必须是有效账户、工作区成员、已主动加入排名的有效参与者。
Workspace 角色或平台 Operator 身份不自动授予他人挑战的管理权。其他有效参与者只能读取当前允许公开的排名字段。
Web 只登记和控制任务，不启动消费者，也不把新任务交回旧同步接口执行。

`RANKING_ENABLED`、`RANKING_PROJECTION_ENABLED`、`RANKING_REBUILD_QUEUE_ENABLED`、
`AUTH_MULTI_USER_ENABLED`、`AUTH_RBAC_ENABLED` 和 `DATA_JOB_WORKER_ENABLED` 必须共同满足才可入队、准备和提交。
默认全部相关新入口关闭。Web 检查 worker 总开关只表示允许排队，不表示执行器已经在线；真正启动入口仍是独立 CLI。
单独关闭队列或 worker 总开关后，已保存任务可由原请求者查看和取消；关闭整个排名/投影入口时，HTTP 访问保持 fail closed。

## 请求与权限快照

- HTTP 请求从当前 session 取得 actor；入队和控制在事务内再次核对 session、账户与挑战所有权。
- `ranking-rebuild-job-v1` 保存挑战、规则、数据截止时间、幂等键指纹，以及账户 authRevision、Membership、参与记录、opt-in/字段授权和删除可见性修订。
- 只读取 session ID、用户归属、起止时间、有效分钟与有效标记用于计分；`xmin` 仅作内部来源修订校验，不作为指标或响应字段。来源改动后再恢复原值也不能复活旧任务。
- 不读取动机、情绪、复盘、笔记/错题正文、附件、AI prompt 或任务标题。昵称和公开字段继续使用挑战、参与者与本人授权的交集。
- DataJob 的内部 JSON、权限快照、源指纹和租约不进入通用任务 DTO；用户导出也不得包含权限快照。
- 浏览器关闭或单设备会话退出不会撤销已接受的后台意图；全账号 authRevision、Membership、挑战或分享版本变化会使原任务失效。新的控制请求仍需当前有效 session。

## 代次、提交与冻结

每个挑战在受控行锁下分配递增 generation，已失败或取消的任务也参与代次计算。
后来的申请不会让较早的任务重新生效；人工重试复用原快照，不能重新绑定更宽权限。需要新快照时应重新申请。

准备阶段读取候选快照；提交阶段在同一 Serializable 事务中重新核对权限、来源、当前 generation 和租约，原子替换整榜并提交任务成功。
删除共享栅栏先于任务行锁，相关行锁使用非阻塞或有限等待；冲突进入退避，不延长通用提交预算。
取消/暂停只在执行器确认后进入终态。发布后租约过期会回滚整次副作用，不能留下半榜或只写成功状态。

读取排名时再次检查参与资格、冻结范围、来源与授权修订；无效快照返回 stale 和空 entries，不继续展示旧分数。
可参与计分的集合在聚合、排序和计数之前过滤。空榜也需要成功任务作为发布证据，不能把“尚未发布”当成已验证空榜。
删除可见性使用现有全局修订，其他对象冻结/解除也可能使排名保守失效；这会增加重新申请次数，但不改写或阻断学习源事实。

## 操作与资源限制

数据与安全页提供申请、当前任务、真实进度、刷新、暂停、恢复、取消、重试和历史记录。
网络响应不明或 2xx 回执损坏时，重试保留同一幂等键；工作区/身份变化废弃旧响应，挑战版本变化立即隐藏旧榜。
临时刷新失败保留可重试控制但隐藏旧分数；明确权限失效时同时清除该作用域的任务与分数。

单次快照最多接受 100 名有效参与者、10,000 条 session 和 20,000 条相关冻结索引记录；超过预算直接拒绝，不截断后发布。
这些是有界执行护栏，不是计费或工作区配额。提交事务最多 15 秒，独立 worker 的真实容量与生产启用仍需目标环境验证。
