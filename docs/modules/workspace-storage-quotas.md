# 工作区附件存储配额

## 范围与配置

`WORKSPACE_STORAGE_QUOTA_ENABLED` 默认关闭；开启时必须显式设置 `WORKSPACE_STORAGE_QUOTA_MAX_BYTES`，
接受规范非负十进制字节数，最大 `9007199254740991`。零拒绝新文件，坏配置只阻断新上传，不阻断学习、已有下载或明确的清理。
适用范围为 note 附件和 FILE 资料；不计导出副本，不提供用户/实例总存储额或跨分区导出次数限制。
实现与验收状态见[平台加固任务](../../tasks/backlog/0045-platform-hardening.md)。

## 计量与准入

附件保存不可变的 `storageWorkspaceId` 计量桶和最小释放状态。桶是内部计量标识，不是授权父关系，不建 FK、不扩大下载、
导出或删除范围，也不随当前活动工作区或资料关联变化转移额度。已结束工作区的桶可保留到附件生命周期结束。
旧 NULL 桶只从唯一且同 owner 的 Note/StudyResource 关系读取，不回填；未知归属、多引用、损坏 metadata 不按零占用处理。

新上传先做原身份/工作区/文件策略校验，再以 Serializable 同事务完成幂等占位、额度判断和 PENDING 文件意图。
有效回执先复用，不再次计量。并发新准入共用有界锁和精确整数字节比较，原始计数不应用冻结可见性过滤。
PENDING、READY、FAILED、归档、冻结和已解绑文件都继续占位；相同 hash 的副本按独立文件身份计量。
资料批次保持逐项结果及批次回执语义：失败项需要一次新的显式批次重试，不用旧错误回执偷偷新建文件。

笔记和资料上传显示受控中文配额提示。失败时保留所选文件与表单输入，提供显式重试；
资料部分失败不阻止成功项完成确认，重试失败文件不会重传已完成项。
丢失服务端回执时保留原请求身份，收到批次结果后的失败项则使用新的显式批次。
笔记成功后清空文件选择，以便再次选择同一文件；两类重试在失败后恢复键盘焦点。

启用时还扫描私有上传命名空间中的文件名、类型、链接数和字节大小，以同一事务查询 metadata；不读正文或向调用者暴露他人文件。
未知文件、已释放文件再次出现、双文件、硬/软链接及扫描中漂移都拒绝新准入。文件增长不得超过已预留大小。

## 文件收口与释放

文件操作先进入删除共享栅栏，再取得按附件身份的排他锁；与冻结交接时宁可有界拒绝，不绕过数据删除保护。
上传确认、skip/reuse、补偿与显式 reconciliation 共用此边界。
copy/finalize 不重复扣款；skip/reuse 的已提交弃用意图不等于文件已清除。

清理验证精确文件身份、hash、size、inode 和路径；双文件或未登记 staging 不自动删除。
只有实际清理、目录 fsync、缺失重验及同事务 CAS 成功后，才保存 `storageReleasedAt` 和绑定完整身份的 `storageReleaseProof`。
证明使用不脱敏的规范化摘要，它不是签名，也不能替代文件检查。已释放身份不能再次激活；重复请求只核验缺失，不借旧意图重新删除再现文件。
失败补偿仅清理可验证的本次 staging，不删除可能已被确认的 final；未知部分文件保留占用。
显式 reconciliation 对确定缺失的新协议意图可在不删除文件的情况下持久结算；不能从 FAILED 或一个布尔结果推断释放。
维护服务可用 `attachmentIds` 收窄候选，空数组不处理任何意图；省略时保持原有有界扫描。
该选择仍叠加 PENDING、新协议、最小年龄、待决资料和 claim/lease 门禁，不授予新的删除权限。
上传进程中断后，完整 staging/final 经显式 reconciliation 校验并提交 READY，同幂等键重试接续原回执；
确定无文件的意图结算后，同键重试创建新文件身份。清理进程在文件持久清除后、释放提交前中断时仍计占用，
新进程重验缺失并提交释放；释放提交后丢失回执的重复请求只核验缺失，保持原证明和释放时间。

阶段 1B-4 的参数观察钩子在真实释放 `updateMany.count=1` 后、事务回调结束前停住：事务内能看到释放，
独立连接仍计原占用并拒绝提前使用额度；SIGKILL 后确认事务及锁退出，再由新进程重验缺失并提交。
staging/final 的提交对照与并发重试均验证单次文件删除、持久释放时间及证明稳定。
同附件竞争在排他事务锁处拒绝，正常协议下不会并发执行释放 CAS；未宣称命中 CAS 谓词冲突。
上述观察钩子只经参数注入，无生产环境变量入口；验收不覆盖网络层 COMMIT 已发送但回执丢失。
具体证据与仍缺的整包门禁见平台加固任务的 STORAGE 阶段 1B-4。

DATA-DELETE 仍遵守既有 owner/对象闭包、冻结 rowHash 和文件 REMOVED 门禁；源行最终删除与账本提交后才自然退出计量。
计量已释放本身不使 FAILED 获得新的删除资格，也不允许沿计量桶反向认领其他数据。
单个 FILE 资料的回收站闭包不反向纳入 Attachment，删除资料后未纳入闭包的文件和原始占用继续保留；
文件物理删除须由原协议可纳入该附件的 owner/工作区闭包执行。定向删除 claim 的过期租约回收也只处理指定 intent。
恢复副本必须先以可信账本重放并验证文件/占用，完成前保持新准入关闭，不能仅信释放时间或旧 marker。

STORAGE 本地恢复专项使用独占合成源的数据库导出快照固定账本 sequence/head，并将水位与实际 dump hash、
文件清单 hash 绑定；恢复工具仅消费本次生成的私有副本，不接受旧域或任意外部备份。
受控源单独固定可信 head，重放输入另从私有账本文件读取；恢复目标复用原冻结计划、文件身份、租约与删除执行器。
恢复前后核对 55 条迁移/checksum 和 schema，失败目标保留隔离；缺文件、双文件、再现文件、身份或归属不明均阻断。

该专项的 `StorageRestoreGate` 仅是 fixture 隔离控制：初始关闭，完成后缀、原始占用与文件核验后才允许一次
服务层合成准入，调用前再次检查可信 head、目标绑定及全表/文件摘要，随后关闭。HTTP 始终关闭。
`WORKSPACE_STORAGE_QUOTA_ENABLED=false` 只关闭配额限制，不能充当恢复锁；该本地控制器不是生产恢复门禁。
执行状态、命令与未覆盖项见[平台加固任务](../../tasks/backlog/0045-platform-hardening.md)的 STORAGE 阶段 1B-3。

## 隐私与回退

计量桶、释放证明和内部文件标识不进入附件 DTO 或用户导出字段；不新增长期使用历史或改变备份保留策略。
关闭新增开关撤回准入限制，保留附件、计量状态、失败意图和审计；文件安全、幂等、冻结和删除确认继续生效。
共享/生产 migration、旧记录回填、历史 orphan 清理及上线须独立确认。
