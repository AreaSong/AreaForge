# 路线图

## 双节点模型

AreaForge 采用“阶段节点 + 终局节点”。

### 第一次同步自测

这是用户自行安排的阶段校准节点：

- 用户按真实考试节奏进行全真自测。
- 自测后写入阶段日记、分数、错题、心态和复盘。
- 系统根据第一次全真结果生成阶段调整草稿，由用户显式确认后更新阶段计划，不自动修改计划或批量重排任务。

### 目标考试日

这是当前考试工作区的终局节点，由用户设置；倒计时和冲刺窗口均读取该日期。系统没有默认年份，未设置时不推测。

## 长期阶段模板

1. 基础唤醒期：建立科目、考纲和稳定行动。
2. 第一次同步自测：获得可量化基线。
3. 复盘重建期：根据真实失分重建投入。
4. 系统强化期：围绕薄弱节点持续复测。
5. 真题专题期：按题型和证据校准。
6. 冲刺模拟期：只在真实目标日期进入窗口时启用。

阶段名称和日期是可编辑计划，不作为代码内置事实。

## 工程阶段

1. 地基：工程骨架、数据模型、首页雏形。
2. 闭环：登录、任务、计时、打卡、复盘真实保存。
3. 进度：考纲树、笔记附件、错题复盘。
4. 鞭策：规则状态、AI 建议、恢复模式。
5. 统计：周报、月报、模拟考试、部署发布。
6. 发布运维：GitHub Release 签名发布、GHCR 镜像 digest、服务器侧 update-agent/updater 受控更新和版本中心只读/请求流。
7. 学习行动中心：五工作台、考试工作区、行动中心、统一复习、计划收件箱、学习树版本导入、关联画布与跨页闭环。规格与批次见 `workflow/versions/v1.1-learning-action-center.md`；进度入口见 `docs/development/feature-traceability.md`。
8. 完整学习闭环增强：今日三阶段进度、断点续学、推荐反馈、完成后继续、学习日结束、每科自然周预算、趋势风险入箱和当前设备收口模板。端到端契约见 `docs/product/learning-loop.md`；当前工作树尚未形成新 Release 或 production apply。

## A -> B 平台演进路线

平台演进坚持个人路径优先、additive-first（先新增兼容结构）、高风险包独立确认、代码/Release/生产分层验收。版本号在各版本冻结时确认，当前建议顺序如下：

| 阶段 | 目标 | 主要交付 | 前置条件 |
|---|---|---|---|
| M0 | 基线归一 | 当前分支 CI/PR、依赖审计、Release/生产/checkout 状态和任务文档收口 | 当前开发分支 |
| v1.3 | 个人版完全动态化 | 多科目/分组首次设置、通用模板目录、重复科目与科目工作台 | M0 |
| v1.4 | 身份与成员 | 邀请制账户、Membership、Workspace 切换、成员与所有权生命周期、租户隔离 | v1.3；AUTH 确认包 |
| v1.5 | RBAC 与隐私授权 | 预设角色、统一授权层、敏感内容显式共享、权限审计 | v1.4；RBAC 确认包 |
| v1.6 | 数据生命周期 | 完整导出、回收站、删除预览、物理删除、备份删除账本 | v1.5；EXPORT/DELETE 确认包 |
| v1.7 | 受控运维中心 | 只读状态、白名单 operation intent、root-only agent、阶段日志与回滚 | v1.5；OPS 确认包 |
| v1.8 | 挑战与排名 | 个人成长指标、私有挑战、主动加入排名、反作弊和删除联动 | v1.5-v1.6；RANKING 确认包 |
| v1.9 | 平台化加固 | 后台任务、通知、搜索、限流、观测、举报申诉、MFA/Passkey 候选 | v1.6-v1.8 |
| v2.0 | 多人学习平台 | 个人和多人路径共同达到发布、生产、安全、隐私与体验门禁 | v1.9 |

### 不变边界

- 个人 Workspace 始终可独立使用，不强迫加入团队或排名。
- `事实 -> 建议 -> 草稿 -> 已确认决策 -> 已应用行动` 的确认链不被多人能力压缩。
- 动机档案、情绪正文、完整复盘、私有笔记/附件和 AI 原始输入默认私有。
- Web runtime 不持有 Docker socket、root 权限、生产 `.env`、备份目录或签名私钥，也不提供任意 shell。
- 排名投影可重建，不反向修改任务、计时、复盘、报告或阶段计划等学习源事实。

详细批次、风险、验证、回滚和完成定义见 `workflow/versions/v1.3-v2.0-platform-evolution.md`。
