# 共享 UI 基础契约

本文定义 AreaForge Web 界面的共享视觉语言、布局原语和交互状态。页面信息架构与逐页布局见 `docs/ux/application-shell-and-workbench-layouts.md`，功能实现状态见 `docs/development/feature-traceability.md`。

公共层的目标是减少认知差异，而不是把所有业务界面抽象成同一个组件。只有跨三个以上页面稳定复用、交互语义一致的能力进入共享层；任务、考纲、复习、模拟等领域组件继续留在各自模块。

## 公共壳层区域

公共壳层使用四类稳定区域，视觉和行为职责不可互换：

- `GlobalTopBar`：全局状态、真正居中的全局命令面板和即时公共工具入口；快捷创建的 `+` 固定在最右侧。
- `PageToolbar`：除 canonical 路由显式声明 `toolbar: "none"` 的 `/focus` 与 `/today` 外，每个页面都挂载的页面级工具栏；左侧面包屑，右侧当前页 actions slot，无动作常规页也保留相同占位高度。它直接承接 `GlobalTopBar`，只用下边线与页面内容分隔，不再通过顶部外边距和上边线制造额外空白层。工具栏是否存在由路由契约决定，不能根据当前按钮数量动态隐藏。
- `GlobalContextStatusBar`：底部上下文状态栏，按“左侧常驻信息、中间进行中工作、右侧系统托盘”组织返回、设备、后台事项、同步与时间，不承载一级主导航；桌面时间固定为 `HH:mm:ss.SSS`，按浏览器绘制帧刷新并保持等宽稳定布局。
- `WindowDock`：单前台工作窗口的后台入口，按父容器真实可用宽度在完整、紧凑和批量收纳间动态切换；移动端统一显示“后台 N”。

全局命令面板的 registry 位于 `apps/web/lib/navigation/command-palette.ts`，UI 位于 `apps/web/components/global-command-palette.tsx`。新增命令应优先追加 registry 定义，不把路由或公共动作硬编码进页面工具栏。

页面 actions slot 由 `PageToolbar` 统一承载。布局使用父容器实际宽度和动作测量结果做响应式决策，不使用“最多显示 N 个”的固定阈值；`ResizeObserver` 触发容器变化时重新计算，只有真正放不下的低频动作才进入菜单。`WindowDock` 的“更多窗口”菜单遵循同一可访问性约束：打开时聚焦首项，支持方向键、`Home`、`End` 和 `Escape`，关闭后恢复触发器焦点。

## 体验原则

- 页面在五秒内给出下一步，不依赖说明墙解释界面。
- 事实、建议、草稿、已应用结果和风险必须能被用户区分。
- 每页至多一个高强调主操作；同一屏不出现多个相互竞争的主按钮。
- 颜色辅助表达语义，但文字、图标和状态标签必须独立可理解。
- 桌面提高扫描和比较效率，移动端保持完整工作流，不压缩成不可读的小型桌面页。
- 失败时保留用户输入并给出恢复动作；成功反馈不遮挡后续操作。
- 不用多层卡片制造层级，页面区块通过间距、分隔线和标题组织。

## 组件归属

### Web 共享层

共享 React primitive 归口 `apps/web/components/ui/**`，包括：

- Shell 区域与页面布局原语。
- 按钮、图标按钮、链接按钮。
- 输入、选择、文本域、复选框、开关和字段反馈。
- Badge、Alert、Empty State、Skeleton、Progress 和 Toast。
- Tabs、Segmented Control、Toolbar、Breadcrumb 和 Pagination。
- Modal、Drawer、Popover、Menu 和 Tooltip。
- 列表、详情面板和数据表格的通用骨架。

### 即时公共工具层

`apps/web/components/global-tool-system.tsx` 管理顶部公共工具的临时浮层。共享底座只负责单一活动工具、定位、响应式尺寸、外部点击、`Escape`、焦点圈定与触发器回焦，不读取业务 API，也不持久化业务正文。AI、恢复帮助和快捷创建分别注册自己的即时内容；恢复帮助和快捷创建没有升级窗口的能力，AI 可显式展开为工作窗口。确认中心不注册即时工具，而是由公共入口或深链直接进入窗口系统。

### 公共工作窗口系统

`apps/web/components/window-system.tsx` 是登录后公共窗口的生命周期容器。它只负责窗口状态，不负责业务内容：

- 响应式固定尺寸预设、单一前台、全局 Portal、背景虚化、最小化、关闭和关闭前确认。
- 后台窗口进入共享 Dock，空间不足时先切换紧凑项，再批量进入“更多窗口”；状态栏左侧按“本机、其他设备、返回上下文”的顺序聚合三类常驻信息，收口与 Dock 位于可伸缩中区，非收口警告、同步和时间组成右侧系统托盘。共享状态详情在桌面端跟随触发区左右对齐。同一收口事实在来源页、前台状态和后台 Dock 之间只出现一次。
- 本地持久化与跨标签页合并，但不让外部标签页抢占当前前台。

只有确认中心、AI 助手和活动收口注册独立 `WindowDefinition`。确认中心有自己的列表/详情导航，并由顶部入口、命令面板或 `/confirmations/*` 深链直接打开；AI 是可框选、多选当前页面元素的上下文工作区；收口按活动类型使用专属内容。快捷创建与恢复求助只注册即时工具，旧持久化窗口会在 Provider 恢复时清理，不能重新出现在 Dock。

共享层不得：

- 直接请求业务 API 或导入 Prisma。
- 理解任务、卡片、错题、报告等领域对象。
- 内置业务文案、权限判断或路由目标。
- 为单一页面提前抽象复杂配置系统。

### `packages/ui`

`packages/ui` 只保留平台无关的稳定 token 和类型，不在只有一个 Web 消费者时迁入 React 组件。出现 PWA、桌面端或其他真实消费者后，再评估提取无 Next.js 依赖的共享组件。

## 设计令牌

### 色彩层级

| Token 语义 | 用途 | 基准色 |
|---|---|---|
| `canvas` | 应用背景 | `#080b0f` |
| `surface-subtle` | 侧栏、工具栏、次级带 | `#0d1117` |
| `surface` | 独立面板、列表容器、浮层 | `#101419` |
| `surface-raised` | 输入、选中项、悬浮面板 | `#151a20` |
| `border` | 默认边界 | `white / 10%` |
| `text-primary` | 标题与主要内容 | zinc 50/100 |
| `text-secondary` | 正文与辅助说明 | zinc 300/400 |
| `text-muted` | 元数据与弱提示 | zinc 500 |
| `accent` | 主操作、当前导航、焦点 | teal 300-500 |
| `info` | 建议、进行中、外部草稿 | sky 300-500 |
| `success` | 已保存、已完成、已应用 | emerald 300-500 |
| `warning` | 待确认、欠账、可恢复问题 | amber 200-500 |
| `danger` | 破坏性动作、阻断错误 | red 300-500 |

颜色使用规则：

- Teal 只表示可执行主操作和当前焦点，不承担所有强调。
- Amber 表示需要注意或确认，不把普通数据都染成告警。
- Red 只用于阻断和破坏性语义，不用于一般未完成状态。
- 大面积背景保持中性深色；彩色区域只用于状态、进度和交互反馈。
- 高对比主题继续使用同一语义，不以反转业务含义换取对比度。

### 圆角、间距与边界

- 圆角只使用 `6px` 和 `8px`：紧凑控件 `6px`，面板与浮层 `8px`。
- 胶囊形只用于真实 badge、状态点和 segmented control，不用于普通文字按钮。
- 基础间距序列为 `4 / 8 / 12 / 16 / 24 / 32px`。
- 页面区块间距默认 `24px`，紧密字段组 `12px`，同类操作间距 `8px`。
- 默认边框为一像素低对比边界；选中态改变边界和背景，不能引发布局位移。
- 阴影只用于浮层和需要从画布抬起的临时表面，普通页面区块不用阴影。

### 字体层级

| 层级 | 尺寸 | 用途 |
|---|---|---|
| Page title | `24px / 32px` | 页面唯一 `h1` |
| Section title | `18px / 28px` | 主要区块 `h2` |
| Subsection title | `16px / 24px` | 面板、列表组 `h3` |
| Body | `14px / 22px` | 默认界面正文 |
| Metadata | `12px / 18px` | 时间、来源、次要状态 |
| Numeric | `24-32px` | 计时和关键数值，使用等宽数字 |

- 不按视口宽度缩放字号，字距保持 `0`。
- 长正文限制可读行宽；工作台标题不使用营销页式超大字号。
- 状态不能只通过粗体或字号表达，必须有可读标签。

### 控件尺寸

| 尺寸 | 高度 | 用途 |
|---|---|---|
| `sm` | `36px` | 桌面紧凑工具栏、行内动作 |
| `md` | `40px` | 默认按钮、筛选和搜索 |
| `lg` | `44px` | 表单主操作、移动端触控 |

- 图标按钮保持正方形和稳定尺寸，动态标签不能改变工具栏高度。
- 移动端主要触控目标不小于 `44 x 44px`。
- 图标采用 Lucide；不熟悉的纯图标按钮必须有 `aria-label` 和 tooltip。

## 页面骨架

### `AppShell`

负责品牌、一级导航、页面顶栏、今日状态、恢复入口、快捷创建、账户和移动底栏。Shell 不限制业务内容最大宽度，也不渲染工作台自己的筛选或页签。

稳定尺寸：

- 桌面展开一级侧栏 `184px`，折叠一级侧栏 `60px`；模块型二级侧栏展开 `216px`，折叠 `52px`。
- 桌面顶栏保持单行 `36px` 控件高度；移动端允许状态/搜索分两行，不能压缩控件触控目标。
- 移动底部导航最小高度 `60px + safe-area`。
- Shell 内容安全边距：移动 `16px`、平板 `24px`、桌面 `24-32px`。

### `PageFrame`

`PageFrame` 只选择四种布局模板：

- `dashboard-wide`：全宽响应式栅格。
- `split-view`：工具栏、列表、详情的稳定轨道。
- `content-focus`：正文或表单保持 `720-960px` 可读宽度。
- `workspace-full`：移除普通内容 padding，由工作区管理自身尺寸。

页面不得再直接组合 `mx-auto max-w-*` 模拟第五种布局。特殊宽度必须先说明内容类型，再落到最接近的模板插槽。

### `PageHeader`

固定插槽：

1. `breadcrumb` 或返回入口。
2. `eyebrow`，仅在需要说明所属工作台时出现。
3. 唯一 `h1`。
4. 可选状态摘要或一句短描述。
5. 可选主操作。
6. 可选更多菜单。

桌面标题与操作可并排，移动端按标题、状态、操作顺序堆叠。业务页面不自行选择另一套标题字号。

### `SectionHeader` 与 `Toolbar`

- `SectionHeader` 只包含区块标题、计数/状态和一个低强调动作。
- `Toolbar` 只承载搜索、筛选、排序、视图模式和批量动作。
- Toolbar 中筛选靠左，视图与批量动作靠右；窄屏按“常用筛选 + 更多筛选”收起。
- 创建命令属于 PageHeader 主操作，不塞进筛选页签。

## 导航原语

### 一级导航

- 包含开始学习、今日、知识、检验、路线；设置位于侧栏底部工具区，确认中心是共享工作流入口。
- 使用图标加文字；折叠侧栏保留图标和 tooltip。
- active 状态同时使用背景、文字和 `aria-current`，不能只变颜色。

### 工作台导航

- 稳定视图使用 `Tabs`；二元或少量互斥模式使用 `SegmentedControl`。
- 二级入口从属于当前一级工作台，视觉权重低于一级；三级内容页沿用共享二级栏，不再在内容区重复渲染二级导航。
- 一级和二级图标都必须有明确业务语义；避免用同一个泛化图标覆盖不同工作台或视图。
- 二级栏标题只作为当前工作台的上下文标签，不重复渲染父级导航图标；顶部共享栏固定提供全局 AI，面包屑右侧直接平铺当前二级视图的常用功能入口，不能替代页面主操作。超过三个入口或窄屏空间不足时，低频入口收进“更多”。
- 筛选值不得伪装成导航页签。例如“周/月”是周期选择，“当前/历史”是报告视图。
- 超过六个日常入口时，低频工具进入 `ToolsMenu`；知识工作台的画布和导入属于工具。
- 移动端 Tabs 可横向滚动，但首尾必须可见，不截断标签文字。

### 返回与面包屑

- 共享面包屑保留当前工作台、二级视图和三级对象；即使工作台首页没有三级对象，也可保留紧凑面包屑，以承载当前视图功能卡。全局 AI 不随面包屑移动，始终位于顶部共享栏。确认中心与活动收口直接使用工作窗口；AI 默认使用即时工具并可显式展开为工作窗口；恢复求助始终是即时工具。
- 详情页显示一个明确返回来源；深层对象最多显示两级面包屑。
- 返回入口优先恢复 `returnTo` 中允许的筛选，再回 canonical 父列表。
- 返回图标使用熟悉的左箭头，文字说明目的地，不使用模糊的“返回上一页”。

## 操作组件

### `Button`

| Variant | 用途 |
|---|---|
| `primary` | 页面唯一主操作 |
| `secondary` | 同页重要但非主流程动作 |
| `ghost` | 工具栏、行内和低频动作 |
| `danger` | 删除、归档、放弃等破坏性动作 |

- 加载状态保留原宽度，显示 spinner 和进行中文案。
- disabled 必须有可理解原因；复杂原因就近显示，不只降低透明度。
- `danger` 不自动成为主按钮；需要确认时进入确认 Modal。
- 链接导航和命令提交在语义上分开，视觉可共享但底层元素必须正确。

### `IconButton` 与 `Menu`

- 熟悉命令优先图标按钮：关闭、更多、搜索、筛选、撤销、下载。
- 删除等高风险命令不能仅靠无标签图标表达。
- 超过三个次级动作收进 `Menu`；最常用动作保持直接可见。
- Menu 关闭后焦点返回触发器，键盘支持方向键和 Escape。

## 数据与状态组件

### 业务事实层级

| 类型 | 推荐组件 | 必须包含 |
|---|---|---|
| 事实 | `Metric` / 普通文本 | 数值、口径或时间范围 |
| 建议 | `SuggestionPanel` | 来源、理由、可否自动应用 |
| 草稿 | `DraftBanner` | 草稿来源、未生效标签、确认/驳回入口 |
| 已应用 | `StatusBadge(success)` | 应用结果和生效时间 |
| 风险 | `Alert(warning/danger)` | 影响、下一步和恢复路径 |

AI、报告和阶段建议统一显示“建议/草稿”身份，并保留 `requiresUserConfirmation` 语义。不得仅通过蓝色或黄色背景暗示它尚未生效。

### `Badge`

- 只表示短状态、类别或计数，不承载完整句子和命令。
- 固定使用文字标签；状态颜色与图标是辅助信息。
- 同一对象同时最多显示三个 badge，其余进入详情。

### `Alert` 与 `Toast`

- `Alert` 用于需要用户阅读或处理的页面内状态，保留到状态改变。
- `Toast` 只用于短暂成功反馈或无需立即处理的通知。
- 表单失败、冲突、离线和保存未完成不得只用 Toast。
- 错误提示包含发生了什么、数据是否保留、下一步如何恢复。
- 动态反馈使用适当的 `role=status`、`role=alert` 与 `aria-live`，避免重复播报。

### 加载、空态与错误态

- 页面首载使用与最终布局同尺寸的 Skeleton，避免布局跳动。
- 局部提交不清空已有内容，只锁定受影响的命令。
- 空态说明“为什么为空”，并提供一个最合理动作；没有动作时不显示装饰性按钮。
- 错误态保留最后可信数据并标明新鲜度；重试不会重复已经成功的写入。
- 无权限、对象不存在、对象已归档和网络失败使用不同文案与恢复路径。

## 表单原语

### 字段结构

每个字段按以下顺序组织：

1. 可见 Label。
2. 可选简短说明。
3. 控件。
4. 校验错误或状态反馈。

- Placeholder 不替代 Label。
- 必填、字符限制和格式在提交前可理解。
- 相关字段使用 `Fieldset` 和 legend，不靠卡片嵌套分组。
- 保存失败时保留输入；服务端冲突提供重新加载、比较或显式重试。

### 二元和选项控制

- 二元设置使用 Switch 或 Checkbox。
- 少量互斥模式使用 Segmented Control。
- 多项枚举使用 Select、Radio Group 或 Menu。
- 数值范围使用 Input、Stepper 或 Slider，并显示单位和合法范围。
- 颜色选择使用可见 swatch，不用纯文字色值代替。

### 表单操作区

- 主操作在左，取消或返回为次级动作；破坏性动作与保存分开。
- 长表单使用稳定操作区，但不能遮挡最后一个字段和错误消息。
- 离开脏表单时统一使用未保存确认，不由各页面重复实现。

## 列表、详情与表格

### `ListDetail`

- 桌面列表列宽稳定，详情使用剩余空间；两侧独立滚动时保留可见选中状态。
- 列表行包含标题、一个主要状态、必要元数据和明确的行内动作。
- 整行可导航时，内部按钮必须保持独立键盘与点击区域。
- 移动端列表与详情分路由；返回后恢复筛选、滚动与选中对象。

### 数据表格

- 只在需要跨行比较三列以上数据时使用表格。
- 表头固定，数值右对齐，状态和操作列宽稳定。
- 手机端优先转换为带字段标签的行，不强制横向滚动；确需横向比较时明确提供滚动容器。
- 空表格使用统一 Empty State，不保留只有表头的空框。

### 卡片

- Card 只用于独立、可重复或整体可点击的对象。
- 页面大区块、表单章节和工具栏不包装成漂浮 Card。
- 禁止 Card 内再嵌套 Card；子层级使用分隔线、列表或无背景分组。

## 浮层

- Modal 用于必须完成或确认后才能继续的短任务。
- 即时公共工具用于所有页面都能快速完成的短流程；内容尺寸由工具自己声明，桌面从顶部工具区展开，移动端映射为底部面板。
- Drawer 用于保留当前页面上下文的页面级辅助流程，如业务详情辅助编辑；它不是公共工具层或工作窗口系统的别名。
- 公共窗口用于需要独立前台、可最小化并可在页面间保留的工作流。窗口内容按业务分别实现，不因共享生命周期而共享导航或表单。
- Popover 用于短信息和少量轻操作，不放长表单。
- Tooltip 只解释图标或陌生概念，不承载关键业务信息。
- 所有浮层都必须锁定焦点、支持 Escape（不可取消的高风险处理中除外）、关闭后恢复焦点并处理移动端安全区。

## 响应式规则

| 范围 | 公共行为 |
|---|---|
| `< 768px` | 单列、底部一级导航、详情独立页面、主控件 `44px` |
| `768-1023px` | 单列或紧凑两栏，侧栏转抽屉，工具栏允许换行 |
| `1024-1439px` | 固定侧栏，可用两栏 ListDetail |
| `>= 1440px` | 全宽 dashboard、三轨 split-view、完整工具栏 |

- 固定格式区域使用 `grid-template-columns`、`minmax()`、`aspect-ratio` 或明确 min/max，动态内容不能推动工具栏和计数器位移。
- 任何断点下都不能出现页面级横向溢出、按钮文字裁切或内容互相遮挡。
- Safe area、虚拟键盘和底部导航必须纳入移动端浮层与固定操作区高度。
- 移动端状态详情从底部状态栏触发，在底部安全区上方展开，必须不遮挡底部导航；关闭时恢复状态按钮焦点。

## 可访问性基线

- 页面有唯一 `h1`，标题层级连续。
- 所有交互可通过键盘完成，焦点样式清晰且不被 sticky 区域遮挡。
- 正文与背景、控件与背景满足 WCAG AA 对比度。
- 状态不能只靠颜色表达；图表有文字摘要或可访问数据表。
- 动效遵循 `prefers-reduced-motion` 和现有体验设置。
- 图标装饰使用 `aria-hidden`，图标命令使用可读名称。
- 错误与字段建立 `aria-describedby` / `aria-invalid` 关联。

## 公共层验收

- 相同语义的按钮、输入、状态、面板不再在业务组件中重复维护颜色和尺寸字符串。
- 四种 PageFrame 模板可以覆盖全部登录后页面，不新增隐式第五套页面宽度。
- Shell、PageHeader、Toolbar、Tabs、Button、Field、Alert、Empty State、ListDetail 和 Overlay 有独立状态示例。
- 组件示例覆盖默认、hover、focus、disabled、loading、error、empty 和长文本。
- 桌面和移动端验证包含高文字缩放、精简动效和高对比主题。
- 公共组件不导入业务服务，不改变认证、数据写入、AI、附件或服务器命令边界。

## 渐进迁移顺序

1. 统一 token、Button、Field、Badge、Alert、Empty State 和 Skeleton。
2. 重构 AppShell、PageFrame、PageHeader、Toolbar 与工作台导航。
3. 以今日和计划验证 dashboard-wide，再以卡片或错题验证 split-view。
4. 迁移复盘和设置的 content-focus，最后处理画布、专注和资料预览的 workspace-full。
5. 每迁移一个工作台就删除对应重复样式与不可达旧组件，不保留长期双实现。

迁移期间允许旧页面继续使用原样式，但新旧公共组件不能在同一页面表达相同语义。兼容 re-export 只用于短期机械迁移，并在对应工作台完成后删除。
