# AreaForge 学习闭环

## 文档定位

本文是 AreaForge 当前学习闭环的端到端产品契约，回答四个问题：

1. 用户从哪里进入当天学习。
2. 一次行动如何执行、收口并留下可信证据。
3. 日复盘、周期判断和下一步行动如何接回同一条链路。
4. 哪些关键行为必须保持一致，后续能力按什么条件进入。

本文只定义跨模块流程和状态语义，不复制各模块的字段、API、数据模型或发布历史：

- 页面和 canonical 路由以 `docs/ux/site-navigation.md` 为准。
- 模块内规则以 `docs/modules/**` 为准。
- 功能覆盖与证据以 `docs/development/feature-traceability.md` 为准。
- 版本实施与历史证据以 `workflow/versions/**` 为准。

## 产品结果

AreaForge 的核心结果不是“记录了多少”，而是让每次学习都回答三个问题：

- 刚才真正完成了什么。
- 这件事留下了什么可复核证据。
- 下一次最应该从哪里继续。

用户即使疲惫，也应能在 5 秒内识别一个可信、可解释、能立即开始的行动；完成后不需要重复录入系统已经知道的事实，也不会因为多个确认步骤失去行动节奏。

## 核心原则

1. **行动优先**：首页先给下一步，不先展示数据墙。
2. **事实优先**：时长、完成记录、复习结果和考试结果从真实记录聚合，不用占位值或推算值冒充事实。
3. **一次只做一件事**：全局同时只有一个活动 session；有活动时先继续或收口。
4. **高频流程最短**：自由学习的启动和收口保持最少必填，深度信息按异常或需要展开。
5. **证据按需产生**：知识卡片、错题和复测是有价值的后续动作，不是每次学习都必须完成的表单。
6. **判断与排期分离**：确认中心决定是否接受判断，投入草稿决定何时做、做多久、关联什么。
7. **人保留最终控制**：规则和 AI 只能生成建议或草稿，不静默修改任务、阶段和用户原始记录。
8. **随时能回到闭环**：离线、刷新、冲突、跨设备或中断后，都应明确显示当前事实和唯一恢复动作。

## 完整闭环

```text
首次设置
-> 今日判断：继续活动 / 推荐行动 / 恢复行动
-> 行动执行：自由学习 / 快速复习 / 专项复测 / 模拟考试
-> 活动收口：记录结果事实和下一步
-> 可选证据：知识卡片 / 错题 / 复测安排
-> 回到今日：继续行动或结束学习
-> 晚间复盘：核对事实，确定明日最低行动
-> 行动安排：草稿转正式任务
-> 周月校准：事实 -> 建议 -> 决策 -> 安排
-> 次日
```

这是一条循环，不是线性向导。用户可以从任务、知识点、复习排期或检验结果进入行动，但每次完成后都应回到“下一步是什么”的判断，而不是停在无后续动作的完成页。

## 状态语义

跨模块信息统一使用以下语义，不把不同成熟度的内容都称为“计划”或“结果”：

```text
事实 -> 建议 -> 草稿 -> 已确认决策 -> 已应用行动
```

| 状态 | 含义 | 允许的来源 | 能否直接改变正式安排 |
|---|---|---|---|
| 事实 | 已发生且可回放的学习、复习、考试或复盘记录 | 用户操作、服务端可信聚合 | 否 |
| 建议 | 基于事实给出的下一步判断 | 本地规则、报告、显式 AI | 否 |
| 草稿 | 可编辑、可忽略、尚未生效的行动候选 | 复盘、报告、阶段、模拟、复测、AI | 否 |
| 已确认决策 | 用户接受或拒绝某个判断后的冻结结果 | 确认中心或来源页显式确认 | 只应用该决策明确声明的范围 |
| 已应用行动 | 已创建的正式任务、已更新的阶段或已确认的排期 | 用户最终应用 | 是 |

必须始终能看出当前对象处于哪一层，以及下一次用户操作会改变什么。按钮文案不使用含糊的“确认”，而应说明“接受建议”“加入投入草稿”“转换为任务”或“应用阶段调整”。

## 入口与工作台职责

| 入口 | 在闭环中的职责 | 不应承担的职责 |
|---|---|---|
| 开始学习 `/focus` | 选择科目并执行自由学习；恢复自由学习收口 | 展示完整今日数据、规划所有任务 |
| 今日 `/today` | 判断当前状态、给出唯一下一行动、承接行动完成和每日闭环 | 展示虚构趋势或替代正式计划管理 |
| 知识 `/knowledge` | 管理知识对象、证据、资料和统一复习 | 直接改变阶段或静默创建任务 |
| 检验 `/test/retests` | 发起专项复测和模拟考试，形成量化结果与补救候选 | 把补救候选直接变成正式任务 |
| 路线 `/roadmap` | 管理投入、阶段、周期复盘和长期校准 | 干扰正在执行的高频学习行动 |
| 确认中心 | 接受、拒绝并冻结一个判断 | 补排期字段、再次编辑完整任务 |
| 投入草稿 | 补全日期、时长、科目和关联，转换为正式任务 | 重复判断建议是否正确 |

### 日常入口目标

登录后的目标行为应由同一个入口解析规则决定：

1. 首次设置未完成：进入考试与科目设置。
2. 存在 `RUNNING`、`PAUSED` 或 `CLOSING` 活动：恢复对应活动或收口。
3. 没有活动且设置完整：进入今日判断。

根入口、已登录登录页和登录成功后的默认回跳必须复用同一入口解析规则；`docs/ux/site-navigation.md` 记录 canonical 路由事实。

## 详细流程

### 1. 首次设置

首次设置只收集能够开始学习的最小信息：

- 考试目标和日期。
- 首个科目。
- 已有数据的保留或归属选择。

设置完成后进入今日判断。动机、提醒、AI Provider、更多科目和个性化偏好按需补充，不阻断第一次学习。

完成条件：用户至少能看到一个科目，并能立即开始自由学习或创建最小任务。

### 2. 今日判断

今日页按固定优先级只给一个主动作：

1. 有活动：继续活动或完成收口。
2. 处于恢复状态：执行一个 30 到 90 分钟的最小行动。
3. 有到期复习：开始下一项快速复习。
4. 有可执行正式任务：开始当前推荐任务。
5. 以上都没有：选择科目自由学习，或创建当天最小任务。

推荐必须能解释来源，例如“今天到期”“昨天留下的下一步”“阶段关键任务”或“恢复模式最低行动”。无法从真实数据得出结论时，显示明确空态，不用默认比例、预测曲线或固定点数填满页面。

今日页同时展示“行动执行 -> 证据接力 -> 每日复盘”三阶段进度轨。最近一次已完成学习若留下下一动作，且当前没有活动或恢复状态，则显示“继续上次”；当前推荐可以标记为“适合当前节奏”或“暂时换一项”，后者只记录反馈并重新计算推荐，不修改正式任务。

### 3. 行动执行

四类行动共用全局唯一活动约束，但保留各自来源和结果：

| 行动 | 启动前置 | 执行重点 | 完成后主要事实 |
|---|---|---|---|
| 自由学习 | 科目 | 专注计时，可选补任务/考纲上下文 | 有效时长、结果、学习产出、下一步 |
| 快速复习 | 有效复习排期和对象 | 查看真实内容并回忆/作答 | 结果、有效时长、下次复习日期 |
| 专项复测 | 科目、知识点和复测范围 | 逐点检验 | 逐点量化结果、反馈和复测结论 |
| 模拟考试 | 考试配置、科目和时长 | 按考试约束完成与录分 | 分科成绩、结构化失分、心态和总结 |

运行中只突出当前对象、时间和暂停/继续/结束。其他工作台入口仍可访问，但顶部和底部持续显示当前活动，避免用户误以为活动已经结束。

### 4. 活动收口

活动结束先冻结时间，再完成收口；未提交前保持 `CLOSING`，刷新或切换页面后仍可恢复。

自由学习的默认必填只保留：

- 结果：达成、部分达成或未达成。
- 实际学习内容与最小产出。
- 下一次从哪里继续。

条件字段按需出现：

- 未达成时要求选择受阻原因。
- 关联正式任务时选择完成、继续或阻塞。
- 理解程度、专注度、精力和补充备注默认可选或折叠。
- 时长、科目、开始结束时间由系统记录，不让用户重复填写。

用户可在 `/settings/learning` 为当前设备修改“实际产出”和“下一动作”的字段提示，并选择是否默认展开可选复盘。模板只改变提示和展开方式，不预填、推断或生成学习事实。

快速复习、专项复测和模拟考试继续使用各自必要的结构化结果，不强行套用自由学习字段。

收口成功后给一个唯一主动作：回到今日判断。创建知识卡片、记录错题、安排复测等证据动作作为次级选择；用户跳过证据也不会丢失本次学习事实。

### 5. 证据接力

证据用于证明理解和安排复测，不用于增加表单负担：

- 形成概念、方法或总结时，创建知识卡片。
- 出现错误或错误思路时，记录错题。
- 需要延迟验证时，创建或调整复习排期。
- 已有关联任务、考纲节点或知识点时，自动带入上下文，用户只核对和修正。

证据保存后返回本次活动完成态或今日页，并明确显示“已经留下什么”和“下一步是什么”。

### 6. 回到今日

每个行动完成后，今日页重新计算优先级并展示：

- 本次新增的真实事实。
- 今日尚未完成的最高优先级行动。
- “继续学习”或“结束今日”的单一主动作。

当日闭环不能只依赖侧栏深层入口。达到用户设定的结束条件、接近复盘时间或当日已有有效学习事实时，今日页应出现清晰的“完成今日复盘”入口。

自由学习、专项复测和模拟考试完成后会重新读取今日推荐：还有可执行项时主操作为“继续下一项”，没有下一项时回到今日；每日复盘完成后入口明确显示“今日已闭环”。

### 7. 晚间复盘

晚间复盘先展示系统已经知道的事实：有效学习时长、任务结果、低转化记录、科目投入、卡片、错题和复测证据。用户不重复填写这些内容，只补充：

- 实际推进。
- 偏差或失控点。
- 最该保留的动作。
- 可选状态。
- 明日最低行动。

保存后冻结当日复盘事实并形成明日最低行动草稿。AI 建议必须由用户显式触发，不能覆盖原始复盘，也不能直接创建正式任务。

### 8. 行动安排

投入草稿承接复盘、低转化、恢复、报告、阶段、模拟、复测和 AI 的行动候选。

处理顺序固定为：

1. 查看来源事实和建议原因。
2. 补全缺失的科目、日期、预计时长和对象关联。
3. 查看将创建什么以及是否有依赖冲突。
4. 显式转换为正式任务，或忽略草稿。

如果草稿字段已经完整，页面直接进入转换预览，不要求用户重新确认建议内容。显式“转换为任务”仍然保留，因为它是从草稿到正式安排的生效边界。

### 9. 周月校准

周期报告先聚合事实，再生成最大短板、下周期焦点和行动建议：

```text
周期事实 -> 建议 -> 接受或驳回判断 -> 行动草稿 -> 正式任务
```

报告确认只冻结报告和接受判断；它不直接修改现有任务。阶段方向需要变化时单独进入阶段建议：

```text
阶段事实 -> 阶段建议 -> 应用阶段调整 -> 派生行动草稿 -> 正式任务
```

确认中心和投入草稿各自只出现一次，不让用户在两个页面回答同一个问题。

路线总览按自然周维护每科投入预算。预算由用户逐科显式保存，可切换周、修改或清空；实际投入和有效投入只聚合该自然周已完成 session。预算用于对比和取舍，不自动创建任务，也不从考纲目标时长或历史投入反推。

趋势页的当前风险可显式加入投入草稿。服务端会重新计算相同 7/30 天窗口并确认风险仍存在，再保存风险类型、严重度、行动、科目、考纲节点和时间范围快照；风险已变化时返回冲突，不使用页面旧数据创建任务。

### 10. 恢复流程

连续失守、完成率长期过低或用户主动求助时，系统暂时降低计划复杂度：

1. 保留一个最小可执行行动。
2. 不要求当天补完全部欠账。
3. 完成后记录真实结果，逐步恢复正常推荐。
4. 动机内容只用于帮助重新行动，不让内容消费替代学习。

恢复状态下仍遵循同一套收口、证据、复盘和草稿边界，不另造一条无法回到日常流程的支线。

## 异常与恢复

| 情况 | 用户应看到什么 | 恢复动作 |
|---|---|---|
| 断网或同步中 | 本机已记录、服务端未确认的明确状态 | 保留本机队列，联网后按序同步 |
| 多标签页或多设备已有活动 | 当前活动的类型、对象、来源设备和状态 | 继续同一活动，不创建第二个 session |
| 收口未完成 | 已冻结时长和仍缺少的最小字段 | 回到 `CLOSING` 继续填写 |
| 版本冲突 | 服务端最新事实、当前本机输入和差异 | 保留输入，重新核对后显式提交 |
| 来源对象失效或归档 | 本次学习事实仍保留，来源不可再使用 | 移除无效关联或返回安全工作台 |
| 没有可推荐数据 | 为什么暂时没有推荐 | 自由学习或创建最小任务 |
| AI 或规则建议失败 | 原始事实和本地可执行路径 | 继续手工创建草稿，不阻断闭环 |

## 关键流程行为契约

以下七项是学习闭环必须长期保持的行为，不表示特定版本、工作树或生产环境的交付状态。实现覆盖、自动化证据和 Release 状态以 `docs/development/feature-traceability.md` 及版本记录为准。

### P0-01 统一日常入口

- 行为：使用本文“日常入口目标”的同一解析规则；设置未完成先设置，有活动先恢复，无活动进入今日判断。
- 验收：根入口、登录回跳、登录成功和非法返回兜底使用同一 resolver，并覆盖三种状态的路由测试。
- 追踪位置：`apps/web/app/page.tsx`、`apps/web/app/login/page.tsx`、`docs/ux/site-navigation.md`。

### P0-02 修正每日复盘入口

- 行为：所有每日闭环入口指向 `/roadmap/reviews/daily`，周期报告入口继续指向 `/roadmap/reviews`。
- 验收：今日页、状态提示和命令入口的文案与实际页面一致，返回后恢复今日上下文。
- 追踪位置：`apps/web/components/action-center-today-view.tsx`。

### P0-03 只展示可信事实

- 行为：所有指标来自可追踪 DTO；没有数据时显示空态或“尚无记录”，不补造趋势和分值。
- 验收：零数据、部分数据和完整数据 fixture 均不出现无法追溯的数字。
- 追踪位置：`apps/web/components/action-center-today-support.tsx`、`apps/web/components/action-center-today-view.tsx`。

### P0-04 让每日闭环可发现

- 行为：满足复盘条件时，今日页显示一个明确入口；完成后显示冻结结果和明日草稿去向。
- 验收：有学习事实、无学习事实、已复盘三种状态都有清晰且不重复的主动作。
- 追踪位置：`apps/web/components/action-center-today-view.tsx`、`docs/modules/dashboard.md`、`docs/modules/review.md`。

### P0-05 简化自由学习收口

- 行为：默认只要求结果、最小产出和下一步；低效原因、任务去向按条件出现，其他字段可选或折叠。
- 验收：普通达成路径可在一个紧凑视区完成；未达成和关联任务路径仍保留必要的反假学习信息。
- 追踪位置：`apps/web/components/focus-session-panels.tsx`、`docs/modules/timer.md`。

### P0-06 分清确认中心与投入草稿

- 行为：确认中心只回答“是否接受判断”；投入草稿只回答“如何安排并应用”。
- 验收：两处标题、说明、按钮和结果反馈使用不同动词，并能查看从事实到正式任务的完整来源链。
- 追踪位置：`apps/web/components/report-decision-actions.tsx`、`apps/web/components/plan-inbox-item-view.tsx`。

### P0-07 减少字段完整草稿的重复操作

- 行为：字段完整时直接展示转换预览和唯一“转换为任务”；字段不完整时只要求补缺失项。
- 验收：保留显式生效确认，但不要求重复录入、重复保存或再次接受同一建议。
- 追踪位置：`apps/web/components/plan-inbox-item-view.tsx`。

## 真实数据边界

- 目标考试倒计时读取当前工作区 `targetExamDate`；模拟节点读取当前工作区下一场真实模拟考试。缺少日期时不触发冲刺、模拟窗口或动机提醒。
- 路线预算读取当前工作区每科、每自然周的 `LearningArrangement(intent=weekly-subject-budget:v1)`；没有显式预算时显示“未设置”，不使用考纲 `targetMinutes`、实际投入或固定时长代替。
- 知识留存、复测和深度没有样本时保持未知并显示空态；模拟考试未录入完整分科满分时保持“满分未录入”。
- 科目和分组在 `/settings/exams` 提供创建、读取、编辑、排序、归档和恢复。科目归档保留学习与排期历史，暂停相关活动排期并清空可执行到期日；恢复科目时只恢复由该次科目归档暂停的排期，并统一安排到当前学习日。分组归档在同一事务中把成员移到“不分组”。
- 408 四科只作为首次设置中默认未勾选的显式模板；登录展示场景中的示例科目不写入用户工作区，也不参与业务统计。

## 已实现闭环增强

以下能力已在当前工作树落地；Release 与生产可用性仍以版本记录和运行证据为准：

| 优先级 | 功能 | 当前行为 | 主要边界 |
|---|---|---|---|
| P1 | 今日闭环进度轨 | 展示行动、可选证据和每日复盘三阶段 | 只读取当日真实聚合，不新增进度状态表 |
| P1 | 断点续学 | 从最近一次已完成 session 的下一动作继续 | 有活动或恢复状态时不抢占主动作 |
| P1 | 推荐解释与反馈 | 展示推荐原因，并支持“适合/换一项” | 反馈写审计；换一项不修改正式任务 |
| P1 | 一键继续下一项 | 行动完成后重新读取今日推荐并直达下一项 | 无推荐时回到来源或今日，不伪造候选 |
| P1 | 学习日结束确认 | 复盘前、已有学习事实、已闭环使用不同动作文本 | 每日复盘仍是显式写入边界 |
| P2 | 周投入预算 | 每科、每自然周创建、修改、清空并对比实际投入 | 预算不自动创建任务，不复用考纲目标时长 |
| P2 | 风险到行动追踪 | 当前趋势风险显式加入投入草稿并保留来源快照 | 服务端重算风险；草稿仍需显式转换 |
| P2 | 个人化收口模板 | 当前设备可配置字段提示和可选区默认展开 | 不预填事实，不跨设备上传 |

新增能力必须优先减少判断和重复操作，而不是增加新的首页卡片、评分或需要维护的状态。

## 验收指标

体验验收应至少用以下指标判断闭环是否改善：

- 无活动时，用户能在 5 秒内识别下一行动。
- 有活动或收口时，任何入口都能恢复同一活动。
- 普通自由学习从点击结束到提交收口不超过一个主要表单视区。
- 今日页展示的每个数字都能追溯到真实记录或明确算法。
- 每日复盘入口在符合条件时可从今日页直接发现。
- 建议、草稿和正式任务在界面上可区分，并能回放来源。
- 一个判断最多确认一次，一个正式写入必须保留一次显式生效动作。
- 完成任一行动后都能回到今日判断或继续下一项，不出现无后续动作的完成页。

## 非目标与边界

- 不为闭环完整而强制每次创建知识卡片、错题或复测。
- 不把 AI 变成自动计划执行器。
- 不在首页复制投入安排、知识库或周期报告的完整功能。
- 不用积分、趋势或预测填补没有数据的状态。
- 不改变认证、权限、附件、AI 隐私、数据生命周期、migration、备份恢复或生产更新边界。
- 本文的 P0/P1/P2 是产品能力分级，不等于 Release 或生产完成声明；当前工作树能力仍需通过完整验证并进入后续 Release，生产 apply 另行确认。
